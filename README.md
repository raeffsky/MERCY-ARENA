# MERCY ARENA

MERCY ARENA — турнирная платформа для Mobile Legends: Bang Bang.

## Публикация

Основной вариант хостинга: **Cloudflare Pages**.

Настройки проекта Cloudflare Pages для Git-интеграции:

- Repository: `raeffsky/MERCY-ARENA`
- Production branch: `main`
- Framework preset: `None`
- Build command: `bash scripts/build-pages.sh`
- Build output directory: `dist`
- Root directory: пусто (корень репозитория)

Скрипт сборки копирует статический сайт и все файлы `public/` в `dist/`. Никакие зависимости или npm-сборка не требуются. Файл `_headers` задаёт базовые HTTP-заголовки и кеширование.

## Разделы

- Главная панель
- Турниры
- Команды
- Игроки
- Центр матчей и сетки
- Рейтинги
- Сезоны
- Статус Auto Result Engine
- Кабинет организатора
- О платформе

Разделы используют отдельные hash-маршруты. Интерфейс адаптивный и сохраняет утверждённую визуальную систему MERCY ARENA.

Личный кабинет поддерживает регистрацию с проверкой MLBB ID, профиль игрока, создание команды, приглашения, управление составом, подачу турнирной заявки с выбором основы и запасных, предпочтительного времени и комментария капитана. Организатор управляет сезонами и турнирами, рассматривает заявки, настраивает временные слоты, формирует поддерживаемые сетки и получает уведомления о действиях. Игроки получают уведомления о решениях по заявкам. Командный и индивидуальный рейтинги рассчитываются только по подтверждённым результатам: 3 очка за победу.

Для текущей схемы платформы применяются миграции из `migrations/` по порядку. Последние изменения: `0013_platform_foundation.sql` (составы заявок, уведомления и персонал турниров), `0014_tournament_time_slots.sql` (временные слоты регистрации), `0015_text_foreign_keys.sql` (намеренно отложена, не выполняет преобразование типов), `0016_double_elimination_advancement.sql` (переходы между верхней и нижней сетками), `0017_season_display_number.sql` (уникальные номера сезонов), `0018_mercy_circuit.sql` (очки, журнал начислений, квалификации и чемпионат) и `0019_archive_teams_players.sql` (архивирование команд и игроков без потери истории). Production D1 использует legacy INTEGER ID для основных сущностей, поэтому `0015` не меняет их типы. Перед применением новых миграций проверь текущую схему и историю D1, сделай резервную копию и не запускай миграции повторно.

## Целостность данных

Демо-турниры, команды, игроки, расписания, результаты и рейтинги не добавляются. Пустые состояния остаются пустыми до подключения доверенного backend.

Auto Result Engine и получение live-результатов MLBB пока не активированы. Платформенная часть управляет аккаунтами, профилями, командами, заявками, сезонами, турнирами, турнирными сетками, уведомлениями и рейтингами. Реализация самих матчей, игровых комнат, check-in, судейской live-операции и автоматического получения результатов вынесена в отдельный этап. Backend: Cloudflare Pages Functions + Cloudflare D1. См. [контракт интеграции backend](docs/BACKEND-INTEGRATION.md).

## Аналитика и контроль качества

PostHog подключается на этапе сборки. В Cloudflare Pages → Settings → Environment variables добавьте для Production и Preview:

- `POSTHOG_PROJECT_TOKEN` — project API token из PostHog.
- `POSTHOG_API_HOST` — `https://eu.i.posthog.com`.

Токен является публичным ключом браузерного проекта, но хранится в настройках сборки, а не в исходниках репозитория. Если переменные не заданы, аналитический SDK не загружается. Встроенный сборщик отправляет просмотры hash-маршрутов и ограниченный autocapture только кликов по ссылкам и кнопкам. Сбор исключений включён. Запись сессий выключена до отдельной проверки настроек приватности.

Локальные проверки:

```bash
npm install
npx playwright install chromium
npm run build
npm run test:e2e
```

GitHub Actions выполняет smoke-тесты на Chromium Desktop и мобильном профиле при каждом push в `main` и pull request. Проверяются главная страница, основная CTA, открытие/закрытие мобильного меню и переходы по маршрутам.
