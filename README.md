# MERCY ARENA

MERCY ARENA — турнирная платформа для Mobile Legends: Bang Bang.

## Публикация

Основной вариант хостинга: **Cloudflare Pages**.

Настройки проекта Cloudflare Pages для Git-интеграции:

- Repository: `raeffsky/MERCY-ARENA`
- Production branch: `main`
- Framework preset: `None`
- Build command: `bash scripts/build-pages.sh`
- Build output directory: `dist`
- Root directory: пусто (корень репозитория)

Скрипт сборки копирует статический сайт и все файлы `public/` в `dist/`. Никакие зависимости или npm-сборка не требуются. Файл `_headers` задаёт базовые HTTP-заголовки и кеширование.

## Разделы

- Главная панель
- Турниры
- Команды
- Игроки
- Центр матчей и сетки
- MERCY MATCH: приватные комнаты матчей, готовность команд и подтверждение результатов судьёй
- Рейтинги
- Сезоны
- MERCY CROWN: история титулов, действующий чемпион и защиты по подтверждённым матчам
- MERCY SCOUT: поиск игроков по роли, региону и подтверждённой игровой статистике
- Статус Auto Result Engine
- Кабинет организатора
- О платформе

Разделы используют отдельные hash-маршруты. Интерфейс адаптивный и сохраняет утверждённую визуальную систему MERCY ARENA.

Личный кабинет поддерживает регистрацию с проверкой MLBB ID, профиль игрока, создание команды, приглашения, управление составом, подачу турнирной заявки с выбором основы и запасных, предпочтительного времени и комментария капитана. Владелец платформы назначает и отзывает глобальную роль организатора, а также отдельно назначает персонал конкретного турнира: организаторов, администраторов, судей и наблюдателей. Приватный кабинет показывает только турниры, к которым аккаунт назначен. Организаторы создают и редактируют черновики, публикуют соревнования, рассматривают заявки, создают сетки и управляют расписанием. Судьи через MERCY MATCH публикуют данные игровой комнаты, контролируют готовность команд и подтверждают результаты с автоматическим продвижением победителя; наблюдатели имеют доступ только на чтение. Попытки обратиться к чужому турниру блокируются на сервере. Игроки получают уведомления о решениях по заявкам. Командный и индивидуальный рейтинги рассчитываются только по подтверждённым результатам: 3 очка за победу.

Для текущей схемы платформы применяются миграции из `migrations/` по порядку. Последние изменения: `0013_platform_foundation.sql` (составы заявок, уведомления и персонал турниров), `0014_tournament_time_slots.sql` (временные слоты регистрации), `0015_text_foreign_keys.sql` (намеренно отложена, не выполняет преобразование типов), `0016_double_elimination_advancement.sql` (переходы между верхней и нижней сетками), `0017_season_display_number.sql` (уникальные номера сезонов), `0018_mercy_circuit.sql` (очки, журнал начислений, квалификации и чемпионат) `0019_archive_teams_players.sql` (архивирование команд и игроков без потери истории), `0020_tournament_stream_url.sql` (ссылка на YouTube-трансляцию в карточке турнира) и `0021_mercy_crown.sql` (история чемпионских правлений и защита титула) и `0022_mercy_crown_single_pending_challenge.sql` (одна активная защита на правление), `0023_mercy_match_rooms.sql` (приватные комнаты матчей и готовность команд). Production D1 использует legacy INTEGER ID для основных сущностей, поэтому `0015` не меняет их типы. Перед применением новых миграций проверь текущую схему и историю D1, сделай резервную копию и не запускай миграции повторно.

## Целостность данных и турнирный цикл

Демо-турниры, команды, игроки, расписания, результаты и рейтинги не добавляются. Пустые состояния остаются пустыми, пока организатор не создаст реальные данные.

Карточка турнира показывает действие по состоянию регистрации: пока приём заявок открыт — «Подать заявку», после закрытия, начала или завершения — «Смотреть турнир». На странице события есть отдельная вкладка трансляции с безопасным YouTube embed; ссылку организатор задаёт в настройках турнира. Если эфир не указан или ссылка неподдерживаемого формата, пользователь видит понятное пустое состояние, а не сломанный плеер.

Платформа поддерживает ручное управление матчами: расписание, перенос, отмену и возврат в расписание, ввод проверенного результата организатором, продвижение победителя по Single Elimination, продвижение победителя и проигравшего по Double Elimination, условный Reset Final и Round Robin. Для изменения завершённого результата используется отдельная владелецкая корректировка с аудитом и каскадной проверкой. Завершённые результаты нельзя менять обычным редактированием. Для исправления есть отдельная операция: она безопасно обновляет несыгранные слоты или каскадно сбрасывает затронутую сыгранную ветку, помечает устаревшие webhook-события как reviewed и повторно открывает завершённый не-Circuit турнир для переигровки. Все изменения выполняются атомарно и попадают в аудит.

MERCY CROWN хранит историю правлений, назначение первого чемпиона и защиты титула через отдельные матчи между чемпионом и претендентом. Победитель определяется только по завершённому и подтверждённому результату; операции доступны только владельцу платформы и попадают в аудит. Назначенную защиту можно отменить с записью в аудит, если матч или событие отменено; на одно правление допускается только одна незавершённая защита. Полный жизненный цикл описан в [документации MERCY CROWN](docs/crown.md). MERCY SCOUT показывает только одобренные неархивные профили, а статистику считает по подтверждённым матчам опубликованных турниров, в которых игрок числился в стартовом составе. Нулевая статистика не подменяется искусственным рейтингом.

MERCY CIRCUIT рассчитывает места по завершённым турнирным сеткам, начисляет очки и хранит append-only журнал транзакций. Исправление результата завершённого обычного Circuit-турнира пересчитывает места и добавляет только разницу очков, не переписывая старые транзакции. Каскад, который потребовал бы переиграть уже сыгранные матчи завершённого Circuit-турнира, пока блокируется: сначала нужна отдельная политика пересчёта сезонных очков. Корректировки квалификаторов и турниров с зафиксированными слотами чемпионата также намеренно заблокированы до отдельного согласования процедуры пересчёта.

Auto Result Engine имеет защищённый HMAC webhook и provider-neutral Cloudflare relay. Это транспорт для доверенного поставщика результатов, а не источник данных: реальный провайдер MLBB пока не выбран и не подключён, поэтому автоматическое получение live-результатов не включено. См. [контракт webhook результатов](docs/results-webhook.md).

Игровые комнаты, check-in, live-судейство и автоматическое получение результатов из клиента MLBB не реализованы. Backend: Cloudflare Pages Functions + Cloudflare D1. См. [контракт интеграции backend](docs/BACKEND-INTEGRATION.md).

## Аналитика и контроль качества

PostHog подключается на этапе сборки. В Cloudflare Pages → Settings → Environment variables добавьте для Production и Preview:

- `POSTHOG_PROJECT_TOKEN` — project API token из PostHog.
- `POSTHOG_API_HOST` — `https://eu.i.posthog.com`.

Токен является публичным ключом браузерного проекта, но хранится в настройках сборки, а не в исходниках репозитория. Если переменные не заданы, аналитический SDK не загружается. Встроенный сборщик отправляет просмотры hash-маршрутов и ограниченный autocapture только кликов по ссылкам и кнопкам. Сбор исключений включён. Запись сессий выключена до отдельной проверки настроек приватности.

Локальные проверки:

```bash
npm install
npx playwright install chromium
npm run build
npm run test:e2e
```

GitHub Actions проверяет синтаксис Functions, сборку и Playwright suite на Chromium Desktop и мобильном профиле. Suite включает UI smoke/regression, API guardrails, генерацию Single Elimination seeding, Circuit scoring и placements, изолированные тесты Circuit reconciliation, progression Double Elimination и provider-neutral relay. Тестовые D1-сценарии используют изолированные mock fixtures; production D1 не изменяется.
